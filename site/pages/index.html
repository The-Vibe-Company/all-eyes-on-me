All Eyes On Me

Coding agents can build a backend on their own, because tests tell them when they got it right. The frontend has no such oracle, so agents improvise: generic screens, a different header on every page, buttons that do not look clickable.

All Eyes On Me gives the frontend that oracle. A fleet of agents rebuilds your app's frontend in parallel, judges every screen, and keeps only what got better.

Star on GitHub

How it works

  1. Capture. It starts your app, follows every link and screenshots each page at phone and desktop width.
  2. Check. It measures what a machine can measure: pointer cursors, sideways scrolling, contrast, console errors.
  3. Judge. Three independent judges look at every page against a short list of principles, and the majority decides.
  4. Directions. On demand, it builds six art directions from things your users know, never from the looks AIs propose by default, and keeps one in a knockout.
  5. Waves. One worker writes the shared kit, then one worker per page rebuilds every page at once, each in its own files.
  6. Ratchet. A page is kept only if fewer things fail on it than before.

Commands

  • aeom capture Find every page of a web app and screenshot it
  • aeom check Run the measurable checks on every page
  • aeom judge Count the judges' votes on the captures
  • aeom principles Print the principles the judge uses
  • aeom snapshot Keep a copy of the captures and reports, such as before a fleet run
  • aeom compare Compare two snapshots page by page
  • aeom sheet Lay captures side by side in one image
  • aeom tournament Run a knockout between directions, three votes per duel

Try it

AEOM is not on npm yet. From the source, with Node 22 and pnpm:

git clone https://github.com/The-Vibe-Company/all-eyes-on-me
cd all-eyes-on-me
pnpm install
pnpm build
pnpm --filter @aeom/core exec playwright install chromium
node packages/cli/dist/index.js --help

Then copy skills/aeom and skills/aeom-judge into your project's .claude/skills/ and type /aeom in Claude Code.

Roadmap

  1. V0, done. The crudest loop that runs end to end, on a deliberately ugly demo app.
  2. Now. This page, rebuilt by AEOM itself.
  3. Next, the UX layer. AEOM understands what an app is for, maps its key journeys, and critiques the existing experience journey by journey. It may reorder steps and navigation, never build features.
  4. Then. Feedback that turns into principles, a spend cap, the npm package.
  5. Later. Codex, mobile, new projects from scratch.

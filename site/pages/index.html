01 Open-source CLI and Claude Code skills

All Eyes On Me

All Eyes On Me is the art director of a product coded by agents: it sets the standard of its front, holds every pull request to it, and builds the front that follows it.

Today, most of the first works. You type /aeom in Claude Code on your app: it takes your front and makes a better one, fixing the UI and the UX on an art direction drawn from your product, or tells you there is nothing to redo.

It runs end to end on demo apps. It has not run on a real project yet, apart from this page, rebuilt by an earlier version.

02 Method

How it works

  1. Understand. It writes what your app is for, who uses it and its main loop, and replays three to five key journeys in a real browser.
  2. Look. It captures every screen at phone and desktop width, measures pointer cursors, sideways scrolling, contrast and console errors, and three independent judges hold each page to eight principles.
  3. Decide. If nothing fails, it says « nothing to redo » and stops.
  4. A new direction. Six art directions drawn from things your users know, never from the looks AIs propose by default, and a knockout keeps one. A client's own style can be kept instead.
  5. Pages, then journeys. One worker per page, then per journey, each in its own files. A guard refuses any change that adds a feature. Only what got better is kept.
  6. Show. A result page on your machine, and the features a blocked journey would need, never built.
  7. The standard, then the PR. The standard of your front, in words: its direction, every token and component with the file it lives in, its own rules. What you correct in it by hand stays. Then a pull request in words, with no capture.

On the demo app, the failures on its four pages went from 10, 8, 8 and 8 to 1, 1, 0 and 0; the measurable checks from 10 to 0; the journeys' failures from 14 to 7; « See my orders » from four steps to three. No feature was added.

04 Legend

Commands

  • aeom capture Find every page of a web app and screenshot it
  • aeom check Run the measurable checks on every page
  • aeom judge Count the judges' votes on the captures
  • aeom principles Print the principles the judge uses
  • aeom snapshot Keep a copy of the captures and reports, such as before a fleet run
  • aeom compare Compare two snapshots page by page
  • aeom sheet Lay captures side by side in one image
  • aeom tournament Run a knockout between directions, three votes per duel
  • aeom product Write the product sheet AEOM drafted, keeping the user's edits
  • aeom journey Replay each key journey and capture every step
  • aeom guard Refuse a change that adds a feature instead of fixing a journey
  • aeom verdict Say whether the front needs redoing, from what AEOM measured
  • aeom report Write the page of what a run gave, in the run's folder
  • aeom features Name what a blocked journey would need, without building it
  • aeom pr Push the run's branch and open a PR, in words, with no capture
  • aeom standard Write the standard of the front, keeping the user's edits

05 Procedure

Try it

AEOM is not on npm yet. From the source, with Node 22 and pnpm:

XR From the source
git clone \  https://github.com/The-Vibe-Company/all-eyes-on-mecd all-eyes-on-mepnpm installpnpm buildpnpm --filter @aeom/core exec \  playwright install chromiumnode packages/cli/dist/index.js --help

Then put aeom on your PATH and the two skills where Claude Code finds them:

XR Link it
mkdir -p ~/.local/bin ~/.claude/skillsexport PATH="$HOME/.local/bin:$PATH"ln -s "$PWD/packages/cli/dist/index.js" \  ~/.local/bin/aeomln -s "$PWD/skills/aeom" \  "$PWD/skills/aeom-judge" ~/.claude/skills/

Your project is a git repository with a clean tree, and your app starts locally with one command, on fake data: its journeys write to it. Type /aeom in Claude Code. A full run is long: on the demo app, about an hour and some sixty subagents.

06 Layers, first to last

Roadmap

  1. Done. Most of level 1, on demo apps: /aeom understands the product, judges every screen and journey, and rebuilds the front on a new direction, or keeps a client's style, and writes the standard of the front.
  2. Now. A bench of apps with known defects, measuring what AEOM finds and fixes.
  3. Next, level 2: keep. Every pull request held to the standard: what can be measured blocks the CI check, the judges comment on whether it is still the same product.
  4. Then, level 3: build. Build what is asked, or a front from scratch, inside the standard, front only.
  5. Later. The judges learn your taste from your feedback, a spend cap, the npm package, Codex, mobile.
